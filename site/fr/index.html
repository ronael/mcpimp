Une seule configuration

Chaque agent référence le même endpoint. Ajouter une intégration ne demande plus de la recopier chez chaque provider.

Des noms d'outils stables

Les outils amont reçoivent un préfixe constant, par exemple amont.get-records. Les agents retrouvent les mêmes noms partout.

Une maintenance centralisée

Sources, variables d'environnement et politiques de mise à jour se gèrent au niveau du registry, pas dans chaque client.

L'unité du registry

Une capability, c'est un dossier. Son identité ne bouge pas.

Un skill (SKILL.md), un MCP amont (mcp.json) ou les deux. MCPIMP reconnaît les composants, indexe les fichiers et expose le tout sous un identifiant public stable — même si l'organisation sur disque change.

ui-skills/improve-ui ui-skills-improve-ui

Les capabilities locales vivent dans le namespace réservé local et gardent leur slug comme ID. Les URIs MCP existantes ne cassent jamais : skill://landing-page/SKILL.md.

Trouver avant de charger

Une recherche classée, pas un dump de fichiers.

Poids par champ, IDF, couverture de la requête, bonus d'exactitude et poids par type de fichier. Une table de synonymes FR/EN légère rapproche « accessibilité » de « accessibility ». Aucun vector store, aucun service externe.

accessibilité ⇄ accessibility composant ⇄ component ameliorer ⇄ improve

Sources & provenance

Tu décides quand le contenu externe entre sur disque.

Un fichier JSON par source dans catalog/sources/. La synchronisation est en lecture seule par défaut ; la politique review attend ton accord explicite avant chaque mise à jour.

› pnpm sources:sync # rapport, rien n'écrit › pnpm sources:sync --apply # accepte les nouveautés
Contenu importé traité comme donnée non fiable — scripts jamais exécutés
Overrides locaux dans overrides/, jamais touchés par la sync
Secrets référencés par env: — rien d'écrit dans mcp.json
Le Worker Cloudflare sert un snapshot statique, sans lire le disque

Périmètre actuel. L’activité MCP locale est journalisée avec expurgation automatique et sans contenu des réponses. Les permissions par agent, le journal d’audit hébergé et le coffre chiffré ne sont pas encore disponibles.

sources:synclecture seule

Importe seulement les skills qui te servent.

Un repo peut contenir vingt skills — tu n'en veux que trois. include et exclude filtrent par slug, roots limite les dossiers scannés. Le reste du dépôt n'entre jamais sur ton disque.

Et ce que tu adaptes localement est protégé : la sync remplace upstream/ à chaque passage, tes fichiers dans overrides/ restent intacts.

Installation locale

Branche le registry à tes agents.

Clone, installe, lance. Puis déclare l'endpoint MCP dans chaque client — HTTP streamable ou SSE selon le transport pris en charge.

Aucun compte ni service distant requis pour le registry et ses capabilities locales.
Terminal
› git clone https://github.com/ronael/mcpimp.git
› cd mcpimp
› pnpm install
› pnpm run dev
Configuration MCP — HTTP streamable
{
  "mcpServers": {
    "mcpimp": {
      "url": "http://localhost:3901/message"
    }
  }
}

› pnpm run build
› npx wrangler deploy
