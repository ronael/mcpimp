Le problème

Les bons workflows existent déjà. Il reste à les retrouver.

Quand les capabilities vivent dans des dépôts, des catalogues et des prompts isolés, chaque nouveau projet recommence le même travail de collecte.

01

Le contexte déborde

Copier des guides entiers dilue la demande et charge des règles sans rapport avec la tâche.

prompt.md + design.md + notes.md + tout le reste
02

La source se perd

Une instruction copiée ne dit plus d’où elle vient, quand elle a changé ni sous quelle licence elle existe.

origine inconnue · révision inconnue · licence inconnue
03

Chaque agent improvise

Sans catalogue commun, Codex ou Claude Code doit deviner quel savoir mobiliser pour chaque projet.

« utilise les bonnes pratiques » ne suffit pas

Ce que MCPIMP change

Un point d’entrée clair pour les capabilities de ton environnement.

Le registry transforme une collection de fichiers en outils MCP explicites, consultables et traçables.

list-capabilities

Découvrir avant d’inventer

Montre à l’agent ce qui est réellement disponible, avec l’origine de chaque capability.

search-capabilities

Trouver le bon passage

Classe les résultats selon le nom, les titres, les tags et le contenu au lieu de tout renvoyer.

load-capability

Charger seulement l’utile

Peut lire une section ou un fichier précis. Le contexte reste centré sur la tâche en cours.

capability-info

Garder une chaîne de confiance

Expose la source, le commit, l’empreinte, la licence et la date de synchronisation.

Fonctionnement

De la source externe au contexte de l’agent, en trois étapes.

La synchronisation et l’exécution sont séparées. Tu décides quand le contenu amont entre sur disque.

Déclaré

Déclare les sources

Ajoute un dépôt GitHub ou un catalogue web autorisé dans catalog/sources/. Les filtres déterminent les capabilities à importer.

Servi

Laisse l’agent choisir

L’agent liste, recherche puis charge la section utile via MCP. Le serveur lit uniquement les fichiers déjà présents.

Requête — MCP› search-capabilities "accessibilité motion landing" › load-capability "elaya-design-landing-page-design"

Tes agents ne devinent plus. Ils découvrent ce dont ils ont besoin, puis chargent seulement l’essentiel.

Sécurité et provenance

Chaque import garde ses papiers.

MCPIMP traite le contenu externe comme une donnée non fiable. Il le conserve avec son identité technique, sans exécuter les scripts importés.

  • Commit, empreinte et licence enregistrés à l’import
  • Catalogues limités par allowedRepositories et mises à jour contrôlées par review
  • Overrides locaux conservés séparément du contenu amont
  • Scripts externes indexés comme texte inerte
  • Secrets référencés par variables d’environnement plutôt qu’écrits dans mcp.json

Périmètre actuel. MCPIMP ne fournit pas encore de permissions par agent, de journal d’audit persistant ni de coffre chiffré. Ces fonctions ne sont donc pas présentées comme disponibles.

Installation locale

Branche le registry à ton agent.

Clone le projet, lance le serveur puis déclare son endpoint MCP dans tes clients. Les agents partagent ensuite le même registre et les mêmes intégrations.

Aucun compte ni service distant ne sont requis pour utiliser le registry et ses capabilities locales.

› git clone https://github.com/ronael/mcpimp.git
› cd mcpimp
› pnpm install
› pnpm run dev
