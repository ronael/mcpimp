Le problème

Les bons workflows existent déjà. Il reste à les retrouver.

Quand les skills vivent dans des dépôts, des catalogues et des prompts isolés, chaque nouveau projet recommence le même travail de collecte.

01

Le contexte déborde

Copier des guides entiers dilue la demande et charge des règles sans rapport avec la tâche.

prompt.md + design.md + notes.md + tout le reste
02

La source se perd

Une instruction copiée ne dit plus d’où elle vient, quand elle a changé ni sous quelle licence elle existe.

origine inconnue · révision inconnue · licence inconnue
03

Chaque agent improvise

Sans catalogue commun, Codex ou Claude Code doit deviner quel savoir mobiliser pour chaque projet.

« utilise les bonnes pratiques » ne suffit pas

Ce que MCPIMP change

Un point d’entrée clair pour les capabilities de ton environnement.

Le registry transforme une collection de fichiers en outils MCP explicites, consultables et traçables.

Découvrir avant d’inventer

list-capabilities montre à l’agent ce qui est réellement disponible, avec l’origine de chaque capability.

Trouver le bon passage

search-capabilities classe les résultats selon le nom, les titres, les tags et le contenu au lieu de tout renvoyer.

Charger seulement l’utile

load-capability peut lire une section ou un fichier précis. Le contexte reste centré sur la tâche en cours.

Garder une chaîne de confiance

capability-info expose la source, le commit, l’empreinte, la licence et la date de synchronisation.

Fonctionnement

De la source externe au contexte de l’agent, en trois étapes.

La synchronisation et l’exécution sont séparées. Tu décides quand le contenu amont entre sur disque.

Déclare les sources

Ajoute un dépôt GitHub ou un catalogue web autorisé dans sources/. Les filtres déterminent les skills à importer.

"repository": "elayadesign/ai-design-skills", "include": ["landing-page-design"]

Synchronise avec contrôle

Le rapport est en lecture seule par défaut. La politique review attend ton accord avant toute mise à jour.

› pnpm sources:sync ↑ update available › pnpm sources:sync --apply source

Laisse l’agent choisir

L’agent liste, recherche puis charge la section utile via MCP. Le serveur lit uniquement les fichiers déjà présents.

› search-capabilities "accessibilité motion landing" › load-capability "landing-page-design"

Tes agents ne devinent plus. Ils découvrent ce dont ils ont besoin, puis chargent seulement l’essentiel.

Sécurité et provenance

Chaque import garde ses papiers.

MCPIMP traite le contenu externe comme une donnée non fiable. Il le conserve avec son identité technique, sans exécuter les scripts importés.

  • Commit et empreinte du contenu enregistrés à l’import
  • Licence détectée et notice conservée avec le skill
  • Scripts externes indexés comme texte inerte
  • HTTPS, hôtes autorisés, limites de taille et chemins validés

Cas d’usage

Un registry commun pour des workflows très différents.

La capability reste l’unité métier. Elle peut contenir des instructions, des références, des données, des scripts ou la configuration d’un MCP amont.

Landing pages

Retrouver une méthode de structure, de rédaction, d’accessibilité et de motion au moment de construire.

Architecture frontend

Charger les conventions d’un projet sans dupliquer un long document dans chaque conversation.

Opérations NocoDB

Exposer un MCP amont sous un préfixe stable et vérifier sa configuration depuis le registry.

Bibliothèque partagée

Versionner les règles locales, suivre les sources externes et déployer un snapshot sur Cloudflare Worker.

Installation locale

Branche le registry à ton agent.

Clone le projet, lance le serveur puis déclare son endpoint SSE dans ton client MCP. Tu gardes la main sur les fichiers et les mises à jour.

Aucun compte, aucune carte bancaire et aucun service distant ne sont nécessaires pour le runtime local.
